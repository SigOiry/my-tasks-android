# Mobile API v1

All `/api/*` endpoints require a full opaque native `Authorization: Bearer <session_token>` or a validated full opaque browser session. Cookie-authenticated unsafe requests additionally require the configured exact Origin and `X-CSRF-Token`. Restricted/bootstrap credentials return428 before data access; after activation the static legacy token and legacy cookies are rejected. An uninitialized legacy token fixture is available only with the explicit compatibility override. See `AUTH-v1.3.md` for the exact additive username/password, private activation, forced-change, native-session, expiry/revocation and logout contract. HTTPS via reverse proxy is required off localhost. `/health` returns only `{"status":"ok"}`.

- `GET /download/my-tasks.apk` is public and serves only server/public/my-tasks.apk; 404 until parent publishes an APK. Never includes token.
- `GET /api/tasks` → `{tasks:[Task], today:"YYYY-MM-DD", week_end:"YYYY-MM-DD", sync:{...}}`. Includes deleted/completed tasks; client groups/filter/sorts priority high/medium/low then due date (null last).
- `GET /api/tasks/{id}` → Task.
- `POST /api/tasks` → 201 Task. JSON editable fields: title (required), description, status, priority, due_date (YYYY-MM-DD or null), project (string or null), notes.
- `PATCH /api/tasks/{id}` → Task; JSON `{revision:"64hex", ...editable fields}`.
- `DELETE /api/tasks/{id}` → soft-deleted Task; JSON `{revision:"64hex"}`.
- `POST /api/tasks/{id}/restore` → Task; JSON `{revision:"64hex"}`.
- `POST /api/tasks/{id}/updates/read` → Task; JSON `{token:Task.notification.token}`. Never ack without displayed exact token.
- `GET /api/events?after=0&limit=100` → `{events:[{id:integer,task_id:string,kind:"created"|"updated"|"deleted"|"restored",token:"64hex",created_at:string}],cursor:integer,has_more:boolean,notification_tracking:boolean}`. Initial poll establishes quiet baseline; no historic flood. Events persist across restarts; poll even if task list unchanged. Metadata only; fetch current task for notification text. `notification_tracking` is true exactly when canonical dashboard notification metadata has been explicitly initialized, not when the SQLite feed baseline exists. Only an explicit false permits fallback alerts for created/updated/restored events even if current task unread is false; missing/unknown tracking never permits fallback. With tracking true, notify only current unread tasks, never already-read tasks. Suppress currently deleted/missing tasks in every mode. Baseline stays quiet and no poll initializes/acknowledges canonical notifications. Meaningful task changes and delete/restore only; ack/timestamp/notes do not alert. Feed detects canonical changes at poll time, not a real-time push service. Events can coalesce between polls. Cursor is last delivered event, preserve it only after notification processing. Native periodic polling is best effort, OS scheduling applies.
- `POST /api/chat` JSON `{task_id:string,message:string,mode:"question"|"email_draft",history?:[{role:"user"|"assistant",content:string}]}` → `{reply:string,mode:string,task_id:string}`. Synchronous compatibility route for older clients only; the current Android/browser clients use the durable async conversation routes below. Old synchronous clients need a read timeout at least180 seconds and proxy upstream/read timeout greater than200 seconds (e.g.210). Provider retries/fallback may extend the 90-second per-request timeout; neither the client deadline nor disconnect cancels provider work. Timeout/network/interruption copy must warn that the original provider request may still be running. Never automatically replay chat; manual re-send may duplicate provider work. The installed configured auxiliary API exposes no per-call retry/fallback limit, so no global/shared provider configuration is modified and no hard end-to-end deadline is claimed. No tools or email send. Task/evidence injected as untrusted context. History max 12 messages; current message and each history content max 8000 Unicode codepoints. Server body cap is 65,536 bytes, including all JSON framing and UTF-8/escaping overhead. Android sends the exact pure-helper serialization at <=60,000 UTF-8 bytes, evicting oldest whole history turns until it fits (omitting out-of-schema history turns). Current message is validated independently, never shortened or trimmed. HTTP 413 means change/shorten the request, not retry the identical payload; Android blocks identical resubmission in the current activity after 413. `503` means unavailable real provider, never fabricated answer.

Task = canonical fields plus notes, deleted, revision, source_accounts, source_links, notification:{unread,token,headline,summary,sections:{context,update,next_steps},updated_at}. Status enum inbox/todo/in_progress/waiting/completed/cancelled; priority high/medium/low. Error JSON `{detail:...}`: 401 unauthenticated, 404 missing, 409 stale revision/notification or duplicate identity, 413 request body too large, 422 invalid, 503 store/provider unavailable. No arbitrary provider/model/URL/tool selection by client.

## Persistent conversations v1.3

These routes use the exact existing `/api` bearer/session authorization, Origin/CSRF, duplicate-security-header rejection, no-store responses, sanitized validation errors and65536-byte body cap. All conversation state is in a separate private `conversations.sqlite`, never the task DB or original Hermes `state.db`. No hard-delete or automatic archive exists. Old `/api/chat` is unchanged/stateless; previously lost stateless history cannot be recovered or imported.

- `GET /api/conversations?scope=all|free|task&task_id=ID&limit=30&cursor=OPAQUE&archived=false` → `{conversations:[Conversation],next_cursor:string|null}`. Default all; task scope requires exact task ID, free selects null task IDs. Updated-descending order with stable descending ID tie; maximum page100. Cursor is filter-bound and opaque. No false totals.
- `POST /api/conversations {task_id:string|null,title?:string}` →201 Conversation. Attached tasks are validated against the saved canonical Store; multiple threads per task are allowed. Title1–200 characters, no blank/control values. Free chat is general-purpose, not limited to tasks.
- `GET /api/conversations/{id}?limit=40&before=CURSOR` → `{conversation:Conversation,messages:[Message],has_more:boolean,before_cursor:string|null,context_compacted:boolean}`. Latest page, oldest-to-newest within it; older cursor pages prepend without duplicates. Maximum page100. Original messages remain complete.
- `PATCH /api/conversations/{id} {expected_revision:integer,title?:string,archived?:boolean}` →Conversation. At least one edit; strict types. Stale revision409. Archive/reopen is recoverable; archived conversations remain readable, but must be reopened before new messages.
- `POST /api/conversations/{id}/messages {request_id:UUID,content:string,mode:'question'|'email_draft',expected_revision:integer}` →202 `{conversation:Conversation,request:Request,user_message:Message}`. Strict1–8000 Unicode-codepoint nonblank content, no client history/provider/tool fields. Persist admission and user message atomically before provider work. Request ID is globally unique: exact conversation/content/mode replay returns its existing state, ignoring the old expected revision, never reruns; changed target/content/mode409. Revision applies to first admission only. One pending reply per thread; global eight-outstanding/two-running bound; overload429 leaves no phantom message.
- `GET /api/conversations/{id}/requests/{request_id}` →Request. Foreign-conversation IDs404. Pending work survives navigation. Startup interrupts orphan jobs and never reexecutes them. Old worker output/summary cannot overwrite interrupted state. Failed/interrupted user messages remain, and explicit retry requires a new identity.

Conversation = `{id:UUID,title:string,task_id:string|null,task_title:string|null,created_at:ISO,updated_at:ISO,revision:integer>=1,archived:boolean,last_preview:string,latest_request:Request|null}`.

Message = `{id:integer,request_id:UUID,role:'user'|'assistant',content:string,created_at:ISO}`.

Request = `{id:UUID,status:'queued'|'running'|'succeeded'|'failed'|'interrupted',error:string|null,assistant_message:Message|null,conversation_revision:integer}`.

UUIDs must be the exact lowercase hyphenated opaque IDs emitted by the API, not normalized/repaired aliases. Revisions must be JSON integers, never booleans or numeric strings. Conversation revision increments on admission, terminal completion/interruption and metadata edits. Request `conversation_revision` reflects current authoritative conversation revision when read. `latest_request` includes terminal as well as pending last requests.

Hermès uses the existing configured auxiliary provider. Normal durable-chat answers may invoke a server-controlled, bounded public-web research loop when external evidence is needed; greetings, ordinary writing, explicit no-browse requests and summaries remain tool-free. Only public search and read-only page retrieval are allowed—no terminal, arbitrary files, email sending, task/calendar mutation or unrestricted agent session. Research receives only the short public latest request, never saved task context/history; private requests fail closed with a privacy notice. Public sources use validated/pinned DNS and checked redirects, response/time/call budgets, and evidence-grounded source URLs saved in ordinary assistant message content. Additive optional `Request.web_phase` is `searching`, `reading`, `answering` or null, reflects actual work, and clears on terminal/restart; old clients may ignore it. Exact accepted-request replay returns persisted state without rerunning research/provider calls. See `qa/backend-public-web/README.md` for network boundaries, real-provider verification and deliberate unsupported cases.

All model history comes from persisted messages; saved task context is read from Store for attached threads. General free questions, analysis and drafts are allowed. Long model context uses a genuine persisted rolling summary plus recent turns, not silently discarded history; `context_compacted=true` indicates persisted summary coverage. Summary/provider failures are sanitized and durably failed, with no fake text or automatic replay. Model input is bounded to44000 Unicode codepoints including fixed instructions, at most12000 saved-task context characters and at most6000 summary characters; original DB content is never truncated. Very large task context is an excerpt, not a claim that the full task was supplied. See README for single-process deployment and scratch-only smoke/seed commands.
