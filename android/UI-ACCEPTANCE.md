# Native UI handoff — 1.3.0 (5)

## Implemented composition

- Two primary destinations: **Tasks / Discussions**. Compact bottom tabs; current window >=720dp splits list and detail. Settings is a utility, not a full-height marketing panel. Menus retain navigation/settings when short-window or IME utility chrome is hidden.
- Task home: one compact toolbar, one view/overflow row, optional search, a small truthful count and a floating rounded primary plus. Project/sort/view choices are menus, not multiple permanently reserved rows. The existing compact XML gives app chrome, controls and opaque rows a **single** vertical scroll; expanded XML retains independent list scrolling. The floating action has bottom content clearance and does not reserve another fixed toolbar row. No nested vertical list scroll or parent cycle was introduced.
- Opaque task rows have68dp minima, dominant16sp/two-line titles, textual unread/high-priority markers and only useful due/project secondary text. Full accessible priority/status/project/due/unread context is retained. Large font scales grow rows rather than shrinking48dp actions.
- Task reading/editing retains exact-token unread acknowledgement, revision-conflict drafts, source-policy confirmation, local calendar labels, task CRUD and recoverable Trash. **Details / Hermès** includes saved task-thread selection and New; unsaved task fields are not sent as model context.
- Global Discussions: All/Free/Task/Archived views, explicit paging, loaded-result search, title/task/preview/pending/failure rows, free creation and reopen. A selected thread menu handles rename/archive/reopen, navigation and task-thread actions. Proposed rename text is retained across errors. No invented agent chooser or imported CLI history.
- Thread messages are selectable safe Markdown in their own weighted scroll, directly above a thread-bound composer (not inside a task-details ScrollView). Link labels are inert and there is no HTML/image engine. Exceptionally long formatted messages show a truthful shortened marker and a full saved plain-text view; stored history is not truncated. Load older prepends complete deduplicated server history. Status/error/compaction hints stay in the message scroll, not in a large fixed banner. Send and mode/voice use48dp labelled vector-icon actions, avoiding large-font button-label clipping. On short windows the input remains multiline/editable but uses one visible line with internal scrolling.
- Accepted provider work is server-owned. Native status updates update message/list surfaces without recreating the composer; newly typed follow-ups survive. Account/target/request guards and per-thread diagnostics prevent another thread's response/error/dictation from being applied here. Same-account layout recreation restores draft/selection/scroll and composer focus/cursor where applicable. These framework interactions still need device QA.

## Materials / motion / accessibility

Light: canvas#f2f2f7, content#fff, ink#1c1c1e, secondary#63636b, separators#d9d9df. Dark: canvas#0b0d12, content#1c1c1e, ink#f5f5f7, secondary#aaaab3, separators#34363d. Light small-text/primary-button blue is the contrast-safe darker#005ac8; dark accent#66aaff uses dark button labels. Automated contrast tests check opaque theme tokens at>=4.5:1. This is not a rendered accessibility audit.

Bundled OFL-licensed Inter, system fallback and app-owned monochrome vectors only. Navigation/composer controls use translucent regular material, a fine rim/gradient highlight and elevation, with high-text-contrast/Reduce transparency opaque fallback. Task/message content stays opaque, not glass cards. Summary/rename/task sheets are rounded inset modals registered for dismissal on logout/expiry; auth gating closes all private layers, not just the underlying root. No backdrop/text blur or proprietary Apple assets; “Liquid Glass-inspired” describes this Android adaptation, not native iOS controls or physical optical refraction.

Native pressed ripples and restrained scale plus brief160–220ms tab/task/sheet/message transitions; system animator/window/transition settings and explicit Reduce motion gate custom motion. Message entrance only follows new turns, not every status poll. The composer is not replaced on provider completion; programmatic message scrolling uses `scrollTo`, not focus-stealing `fullScroll`.
