# v1.6.2 — contextual reply workspace

## Scope and authorization

Implement the owner's complete reply/citation/title request on the existing Android and web surfaces; preserve unrelated task presentation, authentication, exact-update acknowledgement, canonical storage and original Android signer. The new request explicitly authorizes scoped web composer/citation/title UI changes and a contextual Reply action in the update popup. Ordinary AI chat remains unable to send mail or mutate tasks. Development must not send real emails.

## Interaction decisions

- **Entry:** a quiet Reply action beside email context in the update review, plus the same contextual action in task details. Opening it does not mark the update reviewed. Resolve the exact displayed update token. If several responsible messages exist, show a source chooser with sender/subject/date/account; never pick silently. Missing/unresolvable history produces an explanatory unavailable state, not a guessed thread.
- **Composer:** compact header with Close and Review & send; sender account and recipients visible, subject inherited from the thread, short collapsible original-email context, comfortable multiline plain-text editor. Manual writing is the default. Reply/Reply all explicitly changes server-derived participants; do not expose arbitrary account switching or infer a recipient from task prose.
- **Persistence:** one server-authoritative draft, revisioned saves and a visible Saving/Saved/Offline status. Close keeps the draft; an explicit discard action confirms destruction. Network failure keeps local unsaved text. Reopen resumes the same unsent draft and associated AI discussion. Cross-device stale edits surface conflict, never silently overwrite.
- **AI toolbar:** horizontally scrollable compact pills: Draft with AI, Improve writing, Ask AI. AI work is optional and tool-free: relevant source/thread, task/update context and current draft only, never unrestricted mail search or public retrieval.
- **Drafting and writing:** instructions lead to an editable proposal, not replacement. Show a compact Original/Proposed comparison with meaningful word-level changes, Apply and Dismiss. A nonempty draft always receives a preview. Applying requires the matching draft revision; newer typing wins. Offer copy-to-clipboard when a stale proposal cannot safely apply.
- **Ask AI:** persistent draft-bound conversation. Distinguish discussion from proposed editing. Instructions asking to rewrite can produce a proposal, but still require Apply. Neither model text nor tool output can authorize a send or silently edit user text. Preserve unsent AI instructions when switching panels.
- **Sending:** explicit review of exact sender, recipients, original subject/thread and body, then Send reply. Bind confirmation to the immutable reviewed draft revision. Show progress and a durable result; duplicate taps/replayed identities do not send twice. Unknown transport outcome is visibly uncertain and is reconciled, never automatically resent. A late thread update must be shown before a new confirmation.

## Adaptive composition

- **Narrow phone/outer display:** full-height single-column composer with a compact reachable toolbar and IME-safe editor. Ask AI switches to a dedicated full-height chat surface with an obvious Back to draft action; no squeezed split view. Editor and discussion states live outside presentation.
- **Wide inner display:** optional editor/assistant split, approximately 64/36, only when both minimum readable widths fit. Independent scroll; collapsible assistant. Width changes reparent/reflow existing editor state rather than creating a new draft. Preserve focus/selection where platform permits and honor actual insets/available space/folding features.
- **Desktop web:** contextual modal workspace, comfortable maximum text width; Ask AI opens a collapsible, independently scrolling side panel with a resize affordance where practical. Escape closes temporary overlays or saves/closes the workspace, never discards text. Do not bind a keyboard shortcut to immediate sending.
- Respect themes, reduced motion, 48dp native hit targets, keyboard focus, 200% text, portrait/landscape and actual viewport dimensions rather than device models/resolutions.

## Citations and titles

- Fix references at the parsing/storage boundary. Preserve original message content and source links; project a canonical additive source array. Never invent URLs for opaque provider citation IDs. Render compact numbered/source chips opening a small contextual source panel; email sources include authenticated metadata/excerpts, unavailable sources explain their status. Allow multiple sources and safe backward-compatible rendering of old replies.
- Generate concise titles asynchronously after a substantive exchange, from bounded tool-free context. Persist auto/manual origin. Reconsider only after several substantive turns and meaningful topic change, not on each message. Manual rename permanently wins, including races with in-flight generation. Return the same title metadata to all conversation lists/headers.

## Architecture constraints to validate during inspection

Use existing Gmail and Nantes integrations privately on the server. A source must retain provider/account/message/thread identity and be grounded in the exact update, not a URL supplied by the client. Thread replies preserve RFC Message-ID, In-Reply-To, References and Gmail threadId/subject. Do not mirror drafts into mailbox-provider draft folders merely to persist app state. Keep private state separate from task fields; reuse SQLite/revision/admission conventions and authentication/Origin/CSRF protections. Sent messages should be discoverable by the existing outgoing-mail synchronization, without duplicating or reopening canonical tasks.

Browser render/interaction checks at phone, inner-style and desktop widths; native APK build/install and foldable-emulator composition/IME/rotation tests against synthetic data. Explicitly distinguish fixture/provider-contract evidence, real read-only account checks and physical Fold8 validation. Independent security and UX review precedes deployment, original-signer build, source push, CI and stable v1.6.2 publication.
